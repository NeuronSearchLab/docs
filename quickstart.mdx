Build a first recommendation flow with the Core API. This walkthrough uses a shell, `curl` and `jq`. For a managed client, start with [JavaScript](/sdk/introduction), [PHP](/sdk/php), [Next.js](/sdk/nextjs) or [Swift](/sdk/swift). For a website without backend code, use the [no-code start](/instant-start) and [embed](/embed).

## 1. Prepare your workspace

1. [Create an account](https://console.neuronsearchlab.com/signup).
2. Open **Developers → SDK Credentials**, select **New Credential**, and copy the client ID and secret. The secret is shown once.
3. Open **Relevance → Contexts** and copy a context's integer ID. A new workspace includes a starter context; its name depends on your setup.
4. Open **Data → Events → Configure signals** and copy the **Click** event's integer ID. Built-in event IDs can be negative; copy the actual value.

Set `NSL_CLIENT_ID` and `NSL_CLIENT_SECRET` in your server environment. Keep the secret out of browser code, mobile bundles and source control. Set the IDs you copied:

```bash
export NSL_CONTEXT_ID=101  # replace with your context ID
export NSL_CLICK_EVENT_ID=42  # replace with your Click event ID
```

## 2. Get an access token

```bash
NSL_TOKEN_RESPONSE=$(curl --fail-with-body --silent --show-error \
  -u "$NSL_CLIENT_ID:$NSL_CLIENT_SECRET" \
  -d grant_type=client_credentials \
  https://auth.neuronsearchlab.com/oauth2/token)
export NSL_TOKEN=$(printf '%s' "$NSL_TOKEN_RESPONSE" | jq -er '.access_token')
```

The response's `expires_in` tells you how long the token lasts. Reuse it until it needs refreshing. JavaScript, PHP and Next.js clients can handle token exchange and renewal for you. See [Authentication](/integrate/authentication).

## 3. Create two items

Items are the products, articles or other records NSL may recommend. Give each one a useful description and a stable source identifier so repeating this example updates the same records.

```bash
curl --fail-with-body --silent --show-error \
  https://api.neuronsearchlab.com/v1/items \
  -H "Authorization: Bearer $NSL_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '[
    {
      "name": "Trail running shoes",
      "description": "Lightweight running shoes with a waterproof upper.",
      "metadata": {"source_item_id": "quickstart-shoes", "category": "footwear"}
    },
    {
      "name": "Merino running socks",
      "description": "Cushioned wool socks for long trail runs.",
      "metadata": {"source_item_id": "quickstart-socks", "category": "accessories"}
    }
  ]'
```

NSL assigns each item an integer ID. Store those IDs alongside your own records for future updates and events. Check both items in **Data → Items**. For a full catalogue, see [Catalogue](/integrate/catalogue).

## 4. Request a recommendation list

Use an application-owned test user ID. Keep it consistent when recording that user's events.

```bash
NSL_RESULT=$(curl --fail-with-body --silent --show-error --get \
  https://api.neuronsearchlab.com/v1/recommendations \
  -H "Authorization: Bearer $NSL_TOKEN" \
  --data-urlencode 'user_id=quickstart-user' \
  --data-urlencode "context_id=$NSL_CONTEXT_ID" \
  --data-urlencode 'limit=2')
printf '%s\n' "$NSL_RESULT" | jq .
```

The response contains ranked records in `data` and a `request_id`. Each record identifies its item with `item_id`. With a tiny catalogue and no user history, this validates connectivity and retrieval; it does not demonstrate learned personalisation yet.

If `data` is empty, check that the items are active and that your context's filters permit them. [Troubleshooting](/playbooks/troubleshooting) covers authentication, empty results and missing events.

## 5. Record a test click

Copy the first returned item and the request ID directly from the response. This keeps the interaction tied to the list that produced it.

```bash
NSL_ITEM_ID=$(printf '%s' "$NSL_RESULT" | jq -er '.data[0].item_id')
NSL_REQUEST_ID=$(printf '%s' "$NSL_RESULT" | jq -er '.request_id')
# Continue only if both values above were returned successfully.
NSL_EVENT=$(jq -n \
  --arg user_id 'quickstart-user' \
  --argjson item_id "$NSL_ITEM_ID" \
  --argjson event_id "$NSL_CLICK_EVENT_ID" \
  --argjson context_id "$NSL_CONTEXT_ID" \
  --arg request_id "$NSL_REQUEST_ID" \
  '{user_id: $user_id, item_id: $item_id, event_id: $event_id,
    context_id: $context_id, request_id: $request_id}')
curl --fail-with-body --silent --show-error \
  https://api.neuronsearchlab.com/v1/events \
  -H "Authorization: Bearer $NSL_TOKEN" \
  -H 'Content-Type: application/json' \
  -d "$NSL_EVENT"
```

Open **Data → Events** to confirm the test click arrived. In **Insights → Explainability**, enter the `request_id` to inspect the served decision. Keep test traffic separate from real customer identities.

## Build the production flow

Your application repeats the same loop: keep the catalogue current, fetch a list for a user and context, render it, then send actual engagement with that list's request ID.
