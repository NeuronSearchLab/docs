```bash
npm install @neuronsearchlab/sdk
```

The package includes TypeScript declarations, ES module and CommonJS exports. `NeuronSDK` is available as both a default and named export.

## Create a client

```ts
import NeuronSDK from "@neuronsearchlab/sdk";

const sdk = new NeuronSDK({
  baseUrl: "https://api.neuronsearchlab.com/v1",
  oauthClientCredentials: {
    clientId: process.env.NSL_CLIENT_ID!,
    clientSecret: process.env.NSL_CLIENT_SECRET!,
  },
  autoSessionId: false,
  propagateRecommendationRequestId: false,
});
```

This is a server-side example. Explicit session and request IDs prevent concurrent visitors from sharing attribution state on a long-lived client. Do not expose workspace credentials in a browser. Use the [embed](/embed) or your own backend for public clients.

### Authentication options

Configure exactly one:

| Option | Behaviour |
| --- | --- |
| `oauthClientCredentials` | Exchanges `clientId` and `clientSecret`, caches the token and refreshes it. Optional `tokenUrl`, `scope` (string or string array), `audience` and `additionalParameters` customise the exchange. |
| `tokenProvider` | Function receiving `{ forceRefresh, reason }`, returning a token string or `{ accessToken, expiresAt, expiresInSeconds }`, synchronously or as a promise. `expiresAt` is a `Date` or epoch milliseconds. |
| `accessToken` | Static bearer token. You must replace it when it expires. |

A provider's `reason` is `initial`, `expired` or `unauthorized`. Honour `forceRefresh` after a `401`. Refreshable authentication retries an unauthorised request once; a static token cannot refresh itself.

### Client configuration

| Option | Default | Purpose |
| --- | --- | --- |
| `baseUrl` | Required | `https://api.neuronsearchlab.com/v1` |
| `timeoutMs` | `10000` | Per-request timeout |
| `maxRetries` | `2` | Retries for transient HTTP and timeout failures |
| `fetchImpl` | Runtime fetch | Custom fetch implementation |
| `tokenExpirySkewMs` | `60000` | Refresh before expiry; capped at half the token lifetime |
| `collateWindowSeconds` | `3` | Event buffering window |
| `maxBatchSize` | `200` | Flush when the event batch reaches this size |
| `maxBufferedEvents` | `5000` | Buffer capacity; oldest pending events are dropped when exceeded |
| `maxEventRetries` | `5` | Buffered-event retry limit |
| `disableArrayBatching` | `false` | Send events individually |
| `propagateRecommendationRequestId` | `true` | Remember the latest single-list/search request ID |
| `sessionId` | Unset | Default session ID for this instance |
| `autoSessionId` | `true` | Generate an instance session when none is supplied |

## Recommendations

```ts
const result = await sdk.getRecommendations({
  userId: "user-123", contextId: 101, limit: 10,
});
const items = result.data ?? result.recommendations;
```

`getRecommendations(options)` returns `Promise<RecommendationsResponse>`. `userId` is required; optional fields are `contextId`, `limit`, structured `scope`, and `startingAfter` (alias `starting_after`) for pagination. Use the response cursor rather than constructing one.

`getAutoRecommendations(options)` requests a generated section. It accepts `userId`, optional `contextId`, `scope`, `limit`, `cursor`, `windowDays`, `candidateLimit` and `servedCap`. Read `section` for its title, pass `next_cursor` into the next call, and stop when `done` is true or no next cursor is returned. See [Recommendations](/integrate/recommendations).

### Several rails

```ts
const page = await sdk.getRecommendationSets({
  userId: "user-123",
  sets: [
    { key: "for_you", contextId: 101, limit: 8 },
    { key: "similar", contextId: 102, itemId: 3187, limit: 4 },
  ],
});
const rail = page.sets.for_you;
if (rail.error) {
  console.error(rail.error.message);
} else {
  console.log(rail.data, rail.request_id);
}
```

`getRecommendationSets(options)` accepts `userId` or `anonymousId`, optional `sessionId`, `requestId` and a non-empty `sets` array. Each set accepts `key`, `contextId`, `limit`, `itemId`, `cartItemIds`, `pageType`, `filters`, `scope` and `query`. Set keys must be unique and match `[A-Za-z0-9_.:-]{1,64}`.

The result contains ordered `results`, a keyed `sets` map, and usage counts. Check each set's `status` and `error`. Attribute events to that set's `request_id`; a batch does not set one automatic request ID for every rail.

`MAX_RECOMMENDATION_SETS_PER_BATCH` is `8`. Larger explicit set lists are split. An explicit `requestId` is reused for the first chunk only. Do not assume calling a split batch again with the same ID makes every later chunk idempotent.

## Search

```ts
const results = await sdk.search({
  query: "waterproof trail shoes", userId: "user-123",
  contextId: 101, limit: 10, filter: ["category:footwear"],
});
```

`search(options)` returns `SearchResponse`, with `data`, `recommendations`, `request_id` and search information. `query` is required. The options are:

| Options | Purpose |
| --- | --- |
| `userId`, `contextId`, `limit` | Visitor, placement and result count |
| `filter`, `filters` | Shorthand filters; `filters` also accepts structured `{ column, operator, value, logic? }` entries |
| `scope` | Structured object or JSON string containing request constraints |
| `resultItemIds` | Results your own search engine already displayed; NSL returns complementary items |
| `queryRetrievalEnabled`, `fusionMethod` | Enable query retrieval and choose `rrf` or `weighted` fusion |
| `semanticWeight`, `keywordWeight`, `keywordFields` | Tune hybrid retrieval |
| `requestId`, `debug`, `explain`, `includeSuppressed` | Request tracing and explanation controls |

Snake-case aliases exist for the corresponding wire fields. Prefer one spelling consistently. See the [search reference](/api-reference/endpoint/search) for semantics and limits.

## Events and delivery

`trackEvent(payload)` buffers an interaction and returns a promise for its send result. Supply `userId`, integer `eventId` and integer `itemId`; add `contextId`, `requestId`, `sessionId`, `occurredAt` (Unix seconds) and `metadata` as needed.

```ts
const pending = sdk.trackEvent({
  userId: "user-123", eventId: 42, itemId: 3187,
  contextId: 101, requestId: result.request_id,
  sessionId: "visit-456",
});
await sdk.flushEvents();
await pending;
```

Retain the pending promise before flushing in a short-lived process. Awaiting each event inside a loop serialises delivery; enqueue multiple events and then flush if you want a batch. Flush before a worker or request handler exits. Lifecycle flushing is best-effort, not a durable queue.

`trackSearch(payload)` records a search without fetching recommendations. Supply `userId`, `query`, optional `resultItemIds` and the same attribution fields. Omit `itemId`; `eventId` defaults to the workspace's Search signal binding when omitted.

`createEvent(payload)` is a deprecated alias of `trackEvent`. It records an occurrence; it does not create an event type.

`flushEvents({ useBeacon? })` attempts delivery of the current buffer and returns `Promise<void>`. `useBeacon` enables lifecycle-oriented delivery handling. Observe the event promises for delivery errors, and use your own durable event source when loss is unacceptable.

`deduplicationId` is a stable caller-owned occurrence key for retry deduplication. `deduplication_id`, `idempotencyKey`, `idempotency_key`, `messageId` and `message_id` are supported aliases. Reuse a key only for the same event.

## Items

| Method | Input and result |
| --- | --- |
| `createItem<T>(item)` | Creates one item; default result type includes integer `id` and `object: "item"` |
| `upsertItem<T>(itemOrArray)` | Creates or updates one or many items; returns the Core API response. `metadata.source_item_id` identifies repeat imports. |
| `patchItem<T>({ itemId, ...fields })` | Updates fields on an existing item; returns `PatchItemResponse` by default |
| `setItemActive<T>(itemId, active)` | Convenience wrapper around `patchItem` |
| `deleteItems<T>(itemOrArray)` | Deletes one or multiple `{ itemId }` entries; returns `DeleteItemsResponse` by default |

Create payloads contain `name`, optional `description` and `metadata`. Do not send an item ID when creating. Store the returned integer ID; update and delete inputs also accept integer `id` or `item_id` aliases.

```ts
const item = await sdk.createItem({
  name: "Trail shoes", description: "Lightweight waterproof running shoes",
  metadata: { source_item_id: "SKU-42", category: "footwear" },
});
await sdk.patchItem({ itemId: item.id, metadata: { source_item_id: "SKU-42", category: "footwear", price: 120 } });
await sdk.setItemActive(item.id, false);
```

For array creation, provide a response type with `data` when using TypeScript; the older default generic on `upsertItem` does not describe the batch envelope. Generic types describe your expectation and do not validate a response at runtime.

## Client state methods

| Method | Effect |
| --- | --- |
| `setAccessToken(token)` | Replaces authentication with a static token; automatic refresh is no longer used |
| `setBaseUrl(url)` | Changes the API base URL |
| `setTimeout(ms)` | Changes request timeout |
| `setRequestId(idOrNull)` / `getRequestId()` | Set, clear or read the default attribution request ID |
| `setSessionId(idOrNull)` / `getSessionId()` | Set or read the instance session; with auto-session enabled, a missing session may be regenerated |

Automatic request propagation remembers the latest single recommendation, auto-section or search call. It cannot choose the correct rail for a click on an older result. Send explicit IDs for multiple rails, tabs or concurrent users.

## Errors and retries

| Export | Useful fields |
| --- | --- |
| `SDKAuthError` | `message`, optional `status` and `cause` for token acquisition failures |
| `SDKHttpError` | `status`, `statusText`, `body` for an HTTP failure |
| `SDKTimeoutError` | `timeoutMs` for a timed-out request |

Invalid input can also throw a normal `Error`. Transient failures use bounded retry/backoff; validation and permission failures need a corrected request. Handle empty results and failed rails in your UI rather than treating every successful HTTP response as a full list.

## Logging

```ts
import { configureLogger, logger } from "@neuronsearchlab/sdk";
configureLogger({ level: "WARN", enableNetworkBodyLogging: false });
logger.warn("Recommendation fallback used", { contextId: 101 });
```

`configureLogger(config)` and `logger.configure(config)` set `level`, `enableNetworkBodyLogging`, `enablePerformanceLogging`, `transport` and `redactKeys`. Levels are `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`, `FATAL`; the default is `INFO`. Network body and performance logging are off by default.

`logger.trace`, `debug`, `info`, `warn`, `error` and `fatal` accept a message and optional context. `shouldLog(level)`, `canLogNetworkPayloads(level)` and `isPerformanceLoggingEnabled()` inspect the active settings. A custom transport receives a `StructuredLogEntry` with level, numeric level value, message, timestamp and optional context.

Keep body logging off for normal operation: payloads can contain user data. Use `redactKeys` for application-specific fields.

## Type reference

The package exports `SDKConfig`; the authentication types `OAuthClientCredentialsConfig`, `TokenProvider`, `TokenProviderContext`, `TokenProviderReason`, `TokenProviderResult`; item/event types `TrackEventPayload`, `ItemUpsertPayload`, `PatchItemInput`, `PatchItemResponse`, `DeleteItemInput`, `DeleteItemsResponse`; recommendation types `RecommendationOptions`, `AutoRecommendationsOptions`, `RecommendationResource`, `RecommendationsResponse`, `Recommendation`, `RecommendationSetRequest`, `RecommendationSetsOptions`, `RecommendationSetError`, `RecommendationSetResult`, `RecommendationSetsResponse`; search types `SearchOptions`, `SearchStructuredFilter`, `SearchResponse`, `SearchIntentSummary`; and `APIErrorBody`, `LogLevel`, `LoggerConfig`, `StructuredLogEntry`, `LoggerTransport`.

Use these types with the methods above. The [Core API reference](/api-reference/introduction) defines the underlying resource fields.

<Note>
  This reference targets JavaScript 2.3.0. To use [context groups](/console/context-groups), pass their member context IDs as explicit sets in one batch. Group rules apply automatically. This published client version does not expose a `groupId` helper.
</Note>
