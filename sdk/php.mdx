Requires PHP 8.2 or later and cURL, unless you provide an HTTP transport.

```bash
composer require neuronsearchlab/sdk-php
```

## Configure the client

```php
<?php
require __DIR__ . '/vendor/autoload.php';
use NeuronSearchLab\NeuronSDK;

$sdk = new NeuronSDK([
    'baseUrl' => 'https://api.neuronsearchlab.com/v1',
    'oauthClientCredentials' => [
        'clientId' => getenv('NSL_CLIENT_ID'),
        'clientSecret' => getenv('NSL_CLIENT_SECRET'),
    ],
    'autoSessionId' => false,
    'propagateRecommendationRequestId' => false,
]);
```

Use one authentication method: `oauthClientCredentials`, a callable `tokenProvider`, or a static `accessToken`. OAuth credentials support optional `tokenUrl`, `scope`, `audience` and `additionalParameters`. A token provider receives `forceRefresh` and `reason`, returning a token string or an array with `accessToken`, optional `expiresAt` (epoch milliseconds) or `expiresInSeconds`. Refreshable authentication caches tokens and retries one `401` after refresh.

Keep credentials in server configuration. For long-lived Laravel workers, send request and session IDs per event so one client's defaults do not mix visitors.

| Configuration | Default | Meaning |
| --- | --- | --- |
| `baseUrl` | Required | Core API base URL |
| `timeoutMs` | `10000` | Request timeout |
| `maxRetries` | `2` | Transient request retries |
| `tokenExpirySkewMs` | `60000` | Refresh before token expiry |
| `collateWindowSeconds` | `3` | Event age checked during SDK activity; not a background timer |
| `maxBatchSize` | `200` | Flush threshold |
| `maxBufferedEvents` | `5000` | Buffer capacity; oldest events are dropped when exceeded |
| `maxEventRetries` | `5` | Buffered-event retry limit |
| `disableArrayBatching` | `false` | Force individual event sends |
| `propagateRecommendationRequestId` | `true` | Remember the latest single-list/search request ID |
| `sessionId` / `autoSessionId` | Unset / `true` | Instance session and automatic generation |
| `httpClient` | cURL | Callable custom HTTP transport |
| `backoffStrategy` | Built in | Callable retry-delay strategy |

## Recommendations and search

```php
$result = $sdk->getRecommendations([
    'userId' => 'user-123', 'contextId' => 101, 'limit' => 10,
]);
$results = $sdk->search([
    'query' => 'waterproof shoes', 'userId' => 'user-123',
    'contextId' => 101, 'filter' => ['category:footwear'],
]);
```

| Method | Options and result |
| --- | --- |
| `getRecommendations(array $options)` | `userId`, optional `contextId`, `limit`, `scope`, `startingAfter`/`starting_after`; returns a recommendation response array |
| `getAutoRecommendations(array $options)` | `userId`, optional `contextId`, `scope`, `limit`, `cursor`, `windowDays`, `candidateLimit`, `servedCap`; returns a section and continuation state |
| `search(array $options)` | Required `query`; optional `userId`, `contextId`, `limit`, `filter`/`filters`, `scope`, `resultItemIds`, `queryRetrievalEnabled`, `fusionMethod`, `semanticWeight`, `keywordWeight`, `keywordFields`, `requestId`, `debug`, `explain`, `includeSuppressed` |
| `getRecommendationSets(array $options)` | Explicit `sets`, with visitor and attribution options; returns `results`, keyed `sets` and `usage` |

Read `data` or `recommendations` for the single-call result items, and preserve `request_id`. For auto sections, pass `next_cursor` to the next call and stop at `done` or when the cursor is absent.

### Several rails

```php
$page = $sdk->getRecommendationSets([
    'userId' => 'user-123',
    'sets' => [
        ['key' => 'for_you', 'contextId' => 101, 'limit' => 8],
        ['key' => 'similar', 'contextId' => 102, 'itemId' => 3187, 'limit' => 4],
    ],
]);
$rail = $page['sets']['for_you'];
if (!isset($rail['error'])) {
    $items = $rail['data'];
}
```

Batch options include `userId` or `anonymousId`, `sessionId`, `requestId` and a non-empty `sets` array. Set fields are `key`, `contextId`, `limit`, `itemId`, `cartItemIds`, `pageType`, `filters`, `scope`, `query`. Keys must be unique and match `[A-Za-z0-9_.:-]{1,64}`.

`NeuronSDK::MAX_RECOMMENDATION_SETS_PER_BATCH` is `8`. Larger explicit batches are split. Each rail has its own `status`, optional `error` and attribution `request_id`. An explicit batch request ID covers the first chunk only; later chunks receive separate IDs.

## Events and PendingResult

```php
$pending = $sdk->trackEvent([
    'userId' => 'user-123', 'eventId' => 42, 'itemId' => 3187,
    'contextId' => 101, 'requestId' => $result['request_id'],
    'sessionId' => 'visit-456',
]);
$pending->wait();
```

`trackEvent(array $data)` buffers one occurrence and returns `PendingResult`. Use integer event and item IDs, not names. Optional fields include `contextId`, `occurredAt` (Unix seconds), `requestId`, `sessionId`, `metadata`, `query` and a stable `deduplicationId` for retries.

`trackSearch(array $data)` accepts `userId`, a non-empty `query`, optional `resultItemIds`, `eventId` and attribution fields. It records a search without an item. `createEvent(array $data)` is an alias of `trackEvent`, not an event-type creation API.

`flushEvents(array $options = [])` sends the pending buffer. PHP has no SDK background flush timer: flush explicitly in workers and short-lived handlers. The SDK also attempts a shutdown flush, which is not a durable delivery guarantee.

| PendingResult method | Behaviour |
| --- | --- |
| `wait()` | Triggers a flush when pending; returns the result or throws the recorded error |
| `isSettled()` | Reports whether the result has resolved or failed |
| `resolve($value)` / `reject(Throwable $error)` | Settle a result once; intended for custom integrations, not normal event delivery |

To batch, enqueue multiple events before flushing and waiting. Waiting immediately for each event sends them sequentially. Automatic attribution uses only the latest single-list/search call; always pass each rail's ID when displaying several rails.

## Items

```php
$item = $sdk->upsertItem([
    'name' => 'Trail shoes',
    'description' => 'Lightweight waterproof running shoes',
    'metadata' => ['source_item_id' => 'SKU-42', 'category' => 'footwear'],
]);
$itemId = $item['id'];
$sdk->patchItem(['itemId' => $itemId, 'name' => 'Trail shoes — new season']);
$sdk->setItemActive($itemId, false);
```

| Method | Behaviour |
| --- | --- |
| `upsertItem(array $data)` | Creates one item or an array of items. Do not supply an ID. A single result has `id`; a batch has `data`. |
| `patchItem(array $input)` | Updates the integer `itemId` with supplied fields |
| `setItemActive(int $itemId, bool $active)` | Changes availability without deleting the item |
| `deleteItems(array $items)` | Deletes one `['itemId' => 3187]` or a list of such entries |

Set `metadata.source_item_id` to your stable source identifier to update the same item on repeated ingestion. Other arbitrary metadata fields do not enable this matching. Store NSL's generated ID for events and direct `patchItem` updates. PHP does not expose a separate `createItem` method.

## Client state

`setAccessToken(string $token)` replaces refreshable authentication with a static token. `setBaseUrl(string $url)` and `setTimeout(int $timeoutMs)` change connection settings. `setRequestId(?string $id)` / `getRequestId()` manage default attribution; `setSessionId(?string $id)` / `getSessionId()` manage the instance session. With automatic sessions enabled, a missing session may be regenerated.

## Errors and logging

Catch `NeuronSearchLab\SDKAuthError` for token acquisition, `SDKHttpError` for HTTP failures (`status`, `statusText`, `body`), and `SDKTimeoutError` for timeouts (`timeoutMs`). Invalid arguments may throw `InvalidArgumentException`. Retry transient failures with bounded backoff; correct validation and permission errors before retrying.

```php
use function NeuronSearchLab\configureLogger;
use function NeuronSearchLab\logger;
configureLogger(['level' => 'WARN', 'enableNetworkBodyLogging' => false]);
logger()->warn('Recommendation fallback used', ['contextId' => 101]);
```

`configureLogger` configures the shared logger, also available through `SDKLogger::instance()`. Configuration accepts `level`, `enableNetworkBodyLogging`, `enablePerformanceLogging`, `transport` and `redactKeys`. The default level is `INFO`; payload and performance logging are off. Levels run from `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR` to `FATAL`.

Logger methods are `configure`, `trace`, `debug`, `info`, `warn`, `error`, `fatal`, `shouldLog`, `canLogNetworkPayloads` and `isPerformanceLoggingEnabled`. Logging methods take a message and optional context array. Keep user payloads and credentials out of production logs.

## Custom authentication and transport

`httpClient($url, $init)` provides the request transport. Return an array with integer `status`, string `statusText`, an array of `headers`, and a string `body` containing the response. Use this when cURL is unavailable or for controlled tests. `backoffStrategy($attempt)` returns a retry delay in milliseconds. For custom token acquisition, use the supported `tokenProvider` configuration rather than constructing authentication internals.

See [Authentication](/integrate/authentication) and the [Core API](/api-reference/introduction) for the wire contract.

<Note>
  This reference targets PHP 2.3.0. To use [context groups](/console/context-groups), pass their member context IDs as explicit sets in one batch. Group rules apply automatically. This published client version does not expose a `groupId` helper.
</Note>
