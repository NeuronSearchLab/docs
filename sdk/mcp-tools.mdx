This reference covers the package's Core API and administration profiles, plus hosted onboarding tools. Connect using [ChatGPT and MCP](/sdk/mcp). Availability varies by version: inspect your client's live tool list before calling a tool. In the table below, **public** means local Core API mode, **admin** means local `internal` mode, and **hosted** means the hosted administration profile.

Inputs use the names shown here, which may differ from SDK camelCase names. Structured objects follow the relevant [Core API](/api-reference/introduction) or [Platform API](/api-reference/platform-api/introduction) contract. Required fields are marked **required**; other listed fields are optional. The live input schema provides nested fields and validation constraints.

## Core and administration tools

### get_recommendations

Fetch personalised recommendations for a user through the hosted console bridge. Serving a result records attribution and metering data and returns a request_id for subsequent events.

**Available:** public, local, hosted.

| Input | Type | Requirement |
| --- | --- | --- |
| `user_id` | string | **Required** |
| `context_id` | integer | Optional |
| `limit` | integer | Optional |
| `surface` | string | Optional |

### get_recommendation_sets

Fetch every recommendation rail of a page in one request (POST /v1/recommendations/batch). Each set is billed on its own and returns its own request_id — pass the matching one to track_event for interactions on that rail. A set that fails reports its own error without failing the others.

**Available:** public, local.

| Input | Type | Requirement |
| --- | --- | --- |
| `user_id` | string | Optional |
| `anonymous_id` | string | Optional |
| `sets` | array | **Required** |

### get_auto_recommendations

Fetch one auto-generated recommendation section for a user through the hosted console bridge. Serving a section records attribution and metering data and preserves section, next_cursor, and done response metadata.

**Available:** public, local, hosted.

| Input | Type | Requirement |
| --- | --- | --- |
| `user_id` | string | **Required** |
| `context_id` | integer | Optional |
| `limit` | integer | Optional |
| `cursor` | string | Optional |
| `window_days` | integer | Optional |

### track_event

Record a user interaction event (click, view, purchase, etc.), or a search. Always pass the request_id from the recommendations call to enable attribution. Event IDs are configured in the NeuronSearchLab admin console under Events. To record a search, send query (and optionally result_item_ids) with no item_id: it steers the user's recommendations by the weight of the Search event.

**Available:** public.

| Input | Type | Requirement |
| --- | --- | --- |
| `event_id` | integer | Optional |
| `user_id` | string | **Required** |
| `item_id` | integer | Optional |
| `query` | string | Optional |
| `result_item_ids` | array | Optional |
| `request_id` | string | Optional |
| `session_id` | string | Optional |

## Hosted onboarding tools

These tools help a connected customer try sample data and connect a real catalogue. They are additional to the npm package profiles.

| Tool | Inputs | Result and effect |
| --- | --- | --- |
| `try_demo` | Optional `preset`, `limit` (1–10) | Prepares a synthetic workspace and returns its status. Wait for `stage: ready` before rendering results. |
| `get_demo_recommendations` | Optional reserved `user_id`, `limit` (1–10) | Refreshes recommendations for a sample user. |
| `record_demo_interaction` | Required sample `user_id`, integer `item_id`, `action` (`view`, `click`, `purchase`) | Records one synthetic interaction; refresh recommendations afterwards. |
| `render_demo_recommendations` | The complete ready result from `try_demo` | Presents the interactive sample card in a compatible client. |
| `start_using_my_data` | Optional `route`: `catalogue`, `website` or `code` | Returns supported next steps for real data. |
| `connect_my_site` | Required `site_url` | Starts building a catalogue from public pages. |
| `get_onboarding_status` | No inputs | Returns progress and page coverage after connecting a site. |

## Compatibility notes

The local public profile includes `explain_ranking`, but its compatibility route is separate from the documented Core API reference. Use the hosted or local administration profile for the supported Platform API explainability workflow.

Recommendation tools create usage and attribution records. Tools that create, update, delete, enable, disable, activate, start, stop or record data can affect the selected workspace. Keep the assistant's instructions explicit about whether to inspect or apply changes.
