title: "Get recommendation sets"
description: "Every recommendation rail on a page in one request."
openapi: "POST /v1/recommendations/batch"
---

## Description

A page with several rails, such as "For you", "Similar items" and "Trending", can ask for all of them in one request instead of one request per rail. Each set runs exactly as `GET /v1/recommendations` would run it, so a set returns the same results it would return on its own.

The sets share the work they have in common. The visitor's history is read once for the whole page, and two identical sets in one batch are computed once.

Each set is billed as its own recommendation set, the same as a separate `GET /v1/recommendations` call: a batch of five different sets counts as five. Two identical sets in one batch are computed once and billed once.

## Request

```http
POST /v1/recommendations/batch
Content-Type: application/json
```

```json
{
  "user_id": "user-abc123",
  "session_id": "session-42",
  "requests": [
    { "key": "for_you", "context_id": 101, "limit": 12 },
    { "key": "similar", "context_id": 102, "item_id": 3187, "limit": 6 },
    { "key": "vans_only", "context_id": 103, "filters": ["type:van"] }
  ]
}
```

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `user_id` | string | no | End-user identifier, shared by every set. Falls back to the token subject when omitted. |
| `anonymous_id` | string | no | Anonymous identifier for visitors without a `user_id`. |
| `session_id` | string | no | Session identifier for served-recommendation telemetry. |
| `request_id` | string (UUID) | no | Batch ID. Retrying with the same `request_id` gives each set the same request ID, so a retried page is billed once. |
| `requests` | array | yes | One to eight sets. |

Each set takes:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `key` | string | yes | Your name for the rail, unique within the batch. Letters, digits, `_`, `.`, `:` and `-`, at most 64 characters. |
| `context_id` | integer | yes | Context ID generated by the dashboard. |
| `limit` | integer | no | Number of recommendations. Defaults to `20`, maximum `100`. A batch holds at most 200 items in total. |
| `item_id` | integer | no | Seed item for item-to-item contexts. |
| `cart_item_ids` | integer[] | no | Basket items for basket-aware contexts. |
| `page_type` | string | no | Page type, as on `GET /v1/recommendations`. |
| `filters` | string[] | no | Metadata filter shorthand, as repeated `filter` parameters. |
| `scope` | object | no | Request scope, currently honouring `filters`. |
| `query` | string | no | Runs this set as a [search](/api-reference/endpoint/search). |

Pagination (`mode`, `cursor`, `starting_after`) is not part of a batch. Page through a rail with `GET /v1/recommendations`.

## Response

```json
{
  "object": "recommendation_set_list",
  "request_id": "0b8e5f4c-8a37-4c1e-9b0f-3d5f2a6c1e90",
  "results": [
    {
      "key": "for_you",
      "status": 200,
      "request_id": "5b6f3f0e-0d1c-5a7e-9f3b-2c1d4e5f6a7b",
      "context_id": 101,
      "object": "list",
      "data": [
        { "id": "7f3a2c9e", "object": "recommendation", "item_id": 3187, "rank": 1, "score": 0.94 }
      ],
      "limit": 12
    },
    {
      "key": "vans_only",
      "status": 404,
      "request_id": "a1d2c3b4-5e6f-5a7b-8c9d-0e1f2a3b4c5d",
      "context_id": 103,
      "error": { "code": "invalid_context", "message": "Context not found" }
    }
  ],
  "usage": { "sets": 3, "computed": 3, "reused": 0, "coalesced": 0 }
}
```

`results` has one entry per set, in request order. A served set carries the same fields as a `GET /v1/recommendations` response, except the duplicate `recommendations` array. Send each set's own `request_id` with the events from that rail so clicks are attributed to it.

A set that fails comes back with its own `status` and `error`, and the other sets are still served. The batch itself fails only when the request is malformed or unauthorised.

`usage.sets` is the number of sets in the batch. `computed`, `reused` and `coalesced` say how many were ranked, served again from an identical answer a moment earlier, or shared with an identical set in the same batch. Computed and reused sets are billed; a coalesced set is not, and it carries the same `request_id` as the set it shares, since it is the same answer. A reused set carries `reuse: { "reused": true, "age_ms": … }` and its own `request_id`.

## Context groups

Rails that appear together on a page can share rules. On the console's **Contexts** page, drag contexts into a group, then open the group's **Settings**. The order of the rails in a group is their priority: a higher rail claims an item first.

| Rule | What it does |
| --- | --- |
| Don't repeat items across rails | An item appears in one rail at most. The highest rail that ranked it keeps it. |
| Keep rails full | When the group's rules remove items, the rail takes the next ones from its own ranking, so it still fills its `limit`. Turned off, the rail may return fewer items. |
| Limit per attribute across the group | At most N items share one metadata value (for example `author` or `category`) across all the group's rails. |
| Exempt (per rail) | The rail ignores the group's rules, and the items it shows don't count against the other rails. |

The rules apply only when two or more of a group's rails are in the same batch. A rail requested on its own, with `GET /v1/recommendations` or as the only rail of its group in a batch, is served exactly as before. Nothing changes in the request: the batch endpoint, the embed script and the SDKs pick up a group as soon as its contexts are grouped.

Results still come back in request order, each with its own `request_id`, and the served events record what each rail actually showed. Billing doesn't change: each set is still billed as its own recommendation set. Two identical rails in one group are each computed and billed, because the second skips what the first one shows.

## SDKs

```ts
const { sets } = await sdk.getRecommendationSets({
  userId: 'user-abc123',
  sets: [
    { key: 'for_you', contextId: 101, limit: 12 },
    { key: 'similar', contextId: 102, itemId: 3187, limit: 6 },
  ],
});
```

The TypeScript, PHP and Swift SDKs offer `getRecommendationSets`, and `@neuronsearchlab/nextjs` offers `nsl.recommendSets`. Each one splits a page of more than eight sets into several batches for you. The embed script batches placeholders on the same page automatically.

## Errors

| Status | Scenario |
| --- | --- |
| `400` | Malformed body, more than eight sets, more than 200 items in total, a duplicate or invalid `key`, or a pagination field in a set |
| `401` | Missing/invalid access token or tenant resolution failed |
| `403` | Token does not include `neuronsearchlab-api/read` |
| `500` | Unexpected failure before any set ran |
