title: "Get recommendation sets"
description: "Every recommendation rail on a page in one request."
openapi: "/api-reference/openapi.json POST /v1/recommendations/batch"
---

Request several recommendation rails together. Each entry names a context and a unique caller-owned `key`; the results return in request order.

```json
{
  "user_id": "user-123",
  "session_id": "visit-456",
  "requests": [
    {"key": "for_you", "context_id": 101, "limit": 12},
    {"key": "similar", "context_id": 102, "item_id": 3187, "limit": 6}
  ]
}
```

## Limits and partial results

Send one to eight sets, with at most 200 requested items in total. Pagination fields such as `mode`, `cursor` and `starting_after` are not supported within a batch; page an individual rail through [Get recommendations](/api-reference/endpoint/get-recommendations).

Check each result's `status` and `error`. A failed set does not mean the other sets failed. Preserve each successful set's own `request_id` with its items and use that ID for engagement from that rail.

## Billing and retries

Each distinct set counts as a recommendation request. Identical eligible sets in the same batch can share computation and billing. `usage` reports how many sets were computed, reused or coalesced. A reused answer can still be billable; do not interpret reuse as free usage.

Reuse a batch `request_id` only when retrying the same request body. SDKs split lists larger than eight into separate requests; their supplied ID applies to the first chunk, so retrying an entire multi-chunk call does not guarantee deduplication for later chunks.

## Context groups

If at least two contexts in the batch belong to the same [context group](/console/context-groups), its cross-rail rules apply automatically. Send the member context IDs in `requests`; grouping does not require a different client method. Group priority determines which rail keeps a shared item, while the response retains request order.

Keep a group's related rails in the same batch. Rules cannot coordinate rails served in different HTTP requests. Group constraints can make otherwise identical rails produce different results and bill separately.

See [Recommendations](/integrate/recommendations#several-rails-on-one-page) for the integration workflow and [SDKs](/sdk/overview) for language-specific methods.
