Search the catalogue using a free-text query and optional context. This is application search; the Platform API's console search serves a different purpose.

```json
{
  "query": "waterproof trail shoes",
  "user_id": "user-123",
  "context_id": 101,
  "limit": "10",
  "filter": ["category:footwear"]
}
```

## Search and behaviour

When you supply a user or anonymous ID, the request also records a search event. Result items are impressions, not clicks. Record the user's actual engagement separately with the response's `request_id`.

If your own engine ran the search, include its NSL integer `result_item_ids`. NSL records those results and returns complementary recommendations that exclude the supplied items. `search.source` identifies whether the search originated in NSL or your application, and `search.event_recorded` indicates whether it was attached to a user.

Read `data` for results; `recommendations` is a compatibility alias. Preserve explicit attribution when displaying multiple lists or sharing an SDK instance between visitors. See [Search](/integrate/search) for retrieval controls and [Events](/integrate/events#searches-are-events) for search signals.
