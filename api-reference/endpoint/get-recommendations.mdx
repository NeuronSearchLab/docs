Fetch a ranked list for an application user and a [context](/console/contexts). Send the user's stable ID explicitly so different visitors do not share the credential's fallback identity.

```http
GET /v1/recommendations?user_id=user-123&context_id=101&limit=10
```

## Use the response

Read `data` for the ranked results and keep `request_id` with the rendered list. Send that ID with subsequent clicks or purchases to preserve attribution. `recommendations` is a compatibility alias for the same results. Item identifiers are integers.

If the context enables item grouping, the result contains group aggregates rather than a flat item list. This is different from [context groups](/console/context-groups), which coordinate several rails.

For ordinary pagination, use the returned continuation value with `starting_after`. For auto sections, use `mode=auto` and the returned `next_cursor` as `cursor`; stop when `done` is true or no next cursor is available.

The optional `search_intent` and `explanation` fields describe signals that contributed to the ranking. See [search signals](/integrate/events#how-searches-steer-recommendations) and [Explainability](/console/explainability) to interpret them.

See [Recommendations](/integrate/recommendations) for similar-item rails, baskets, anonymous users and filtering. Use the batch endpoint for several rails on one page.
