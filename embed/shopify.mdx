The NeuronSearchLab Shopify extensions add the recommendation widget to your
theme and supply it with context from the storefront. Shopify already knows
which product a page shows, what is in the basket, who is signed in and what
was bought; the app reads each of those and passes them to the widget.

It has two parts: a theme app embed that loads the widget and reports page,
cart and customer context, and a web pixel that reports completed orders from
checkout.

<Note>
  The app covers the manual steps described on the main embed page. With it installed you do not need [page context](/embed#page-context), [category and search](/embed#category-and-search-pages) or [conversions](/embed#conversions).
</Note>

## Availability

The Shopify Partner app is registered and its theme and web-pixel extensions
are deployed. The public App Store listing is still in review preparation, so
there is no public install link yet. To evaluate the integration on a Shopify
development store, contact [NSL support](mailto:support@neuronsearchlab.com).
The development app has been installed on an isolated test store; a complete
checkout and self-service account-linking flow have not yet been verified.

## Set up the storefront

After NSL gives your store access to the app, complete these steps in order:

<Steps>
  <Step title="Add the app">
    Install **NeuronSearchLab** in your Shopify admin. During the current
    evaluation period NSL must grant access to your store. Public App Store
    installation will be available after Shopify review.
  </Step>
  <Step title="Connect your catalogue">
    Sign in to the [NSL console](https://console.neuronsearchlab.com/login).
    Open **Integrations → Shopify**, enter your `*.myshopify.com` domain and
    choose **Authorize with Shopify**. Approve the requested access in Shopify,
    then return to the NSL console. During the current evaluation period, ask
    NSL support to confirm the development store is linked to your workspace.
    Check that products appear in **Users & Items** before enabling a strip.
    Existing stores with a previously issued Admin API token may use the
    legacy-token option in the same integration panel.
  </Step>
  <Step title="Create an embed key">
    In the console, **Developers → Website embed**. Add every storefront
    domain to the key's origins, including the `*.myshopify.com` domain and
    custom domains you preview from. Copy the publishable key (`nsl_pk_...`).
  </Step>
  <Step title="Turn on the app embed">
    In Shopify, open **Online Store → Themes → Customize → App embeds →
    NeuronSearchLab**. Paste the publishable key, enable the embed, and save.
    The widget then loads on storefront pages and reports page context.
  </Step>
  <Step title="Place a strip">
    In the theme editor, add the **Recommendations** app block to a supported
    template and save. Give it a placement name if you want to configure it
    from the console later. Visit that page and confirm products appear.
  </Step>
  <Step title="Configure checkout reporting">
    Shopify web pixels are managed separately from theme embeds. In **Settings
    → Customer events**, confirm the NeuronSearchLab app pixel is connected
    and uses the same publishable key. Test a completed checkout before
    relying on conversion reports; the current development installation has
    not passed that check yet.
  </Step>
</Steps>

## What the app sends

Each value comes from Shopify's own objects, so there is no tagging to write
and nothing to keep correct as your theme changes.

| Shopify | Becomes |
| --- | --- |
| `product.selected_or_first_available_variant.sku` | the item this page is about |
| `collection.handle` | the category a listing page is showing |
| `search.terms` | the search a visitor just ran |
| `cart.items` | the basket, on every page |
| `customer.id` | who is signed in, hashed per workspace before anything is stored |
| `checkout_completed` | the sale |

## Conversions

Orders are reported by a web pixel rather than by theme code, because
Shopify's checkout is not part of your theme and no theme code runs there.

They arrive as the `order_reported` signal, bound by default to a zero-weight
event, because a browser cannot prove a sale took place. They are used for
attribution and revenue reporting. Product views and basket additions come from
the app embed as `view` and `add_to_cart`; see [Events](/embed#events).

For verified orders as well, grant `read_orders` when connecting Shopify in
**Integrations**. This access is subject to Shopify's protected customer-data
review for a public app. Browser-reported and verified orders use the same
order ID, allowing the verified event to supersede the reported one.

## Placements

A strip placed in the theme decides where recommendations appear. What it
serves, how many items it shows and how each card reads are set by the
placement in the console, so those change without a theme edit or a deploy.

A placement the console does not recognise still renders, using your workspace
defaults, so renaming one does not blank a live page.

## Privacy

Where your shop uses Shopify's customer privacy API and a visitor has not
allowed analytics, the widget continues to render recommendations but stops
describing the visitor: cart and customer are withheld.

The storefront embed sends the customer **id**, rather than a name, email or
address. It is hashed with a per-workspace key before storage. If order
history is enabled, NSL reads the order customer ID or guest email from
Shopify's Admin API and hashes that identifier before storing training rows.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| No strip renders | The app embed is off, or the key is missing from it |
| Strip renders on some domains only | A storefront domain is not on the key's origins — the console's **Website embed** page lists any it turned away |
| Strip looks unrelated to the product | The product's SKU is not in your catalogue. Add `?nsl_debug=1` to the page and the overlay says so |
| Conversions not appearing | The web pixel needs the same embed key; check **Settings → Customer events** |
