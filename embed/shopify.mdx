The NeuronSearchLab Shopify app installs the recommendation widget into your
theme and supplies it with context from the storefront. Shopify already knows
which product a page shows, what is in the basket, who is signed in and what
was bought; the app reads each of those and passes them to the widget.

It has two parts: a theme app embed that loads the widget and reports page,
cart and customer context, and a web pixel that reports completed orders from
checkout.

<Note>
  The app covers the manual steps described on the main embed page. With it installed you do not need [page context](/embed#page-context), [category and search](/embed#category-and-search-pages) or [conversions](/embed#conversions).
</Note>

## Install

<Steps>
  <Step title="Add the app">
    Install **NeuronSearchLab** from the Shopify app store.
  </Step>
  <Step title="Create an embed key">
    In the console, **Developers → Website embed**. Add every storefront
    domain to the key's origins, including any you preview from.
  </Step>
  <Step title="Turn on the app embed">
    **Theme editor → App embeds → NeuronSearchLab.** Paste the key and save.
    The widget now loads on every page and reports context.
  </Step>
  <Step title="Place a strip">
    Drag **Recommendations** into any template. Give it a placement name if
    you want to configure it from the console later.
  </Step>
</Steps>

## What the app sends

Each value comes from Shopify's own objects, so there is no tagging to write
and nothing to keep correct as your theme changes.

| Shopify | Becomes |
| --- | --- |
| `product.selected_or_first_available_variant.sku` | the item this page is about |
| `collection.handle` | the category a listing page is showing |
| `search.terms` | the search a visitor just ran |
| `cart.items` | the basket, on every page |
| `customer.id` | who is signed in, hashed per workspace before anything is stored |
| `checkout_completed` | the sale |

## Conversions

Orders are reported by a web pixel rather than by theme code, because
Shopify's checkout is not part of your theme and no theme code runs there.

They arrive as `purchase_reported`: a separate event, weighted 0 and excluded
from model training, because a browser cannot prove a sale took place. They
are used for attribution and revenue reporting.

For verified orders as well, connect Shopify in **Integrations** with
`read_orders`. Both paths key on the same order id, so the verified order
supersedes the browser's report rather than adding to it, and a sale is never
counted twice.

## Placements

A strip placed in the theme decides where recommendations appear. What it
serves, how many items it shows and how each card reads are set by the
placement in the console, so those change without a theme edit or a deploy.

A placement the console does not recognise still renders, using your workspace
defaults, so renaming one does not blank a live page.

## Privacy

Where your shop uses Shopify's customer privacy API and a visitor has not
allowed analytics, the widget continues to render recommendations but stops
describing the visitor: cart and customer are withheld.

Only the customer **id** is ever sent, and it is hashed with a per-workspace
key before storage. No name, email or address leaves the page.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| No strip renders | The app embed is off, or the key is missing from it |
| Strip renders on some domains only | A storefront domain is not on the key's origins — the console's **Website embed** page lists any it turned away |
| Strip looks unrelated to the product | The product's SKU is not in your catalogue. Add `?nsl_debug=1` to the page and the overlay says so |
| Conversions not appearing | The web pixel needs the same embed key; check **Settings → Customer events** |
